count <- array[0 … max_val−min_val] initialized to 0
for each num in arr do
    count[num−min_val] <- count[num−min_val] + 1

Loop invariant P(k):
after processing the first k elements of arr, for every value v in [min_val … max_val],
count[v−min_val] equals the number of times v appears in arr[0 … k−1].

- Initialization (k = 0): No elements processed, so all entries are 0. Matches P(0).
- Single iteration (k = 1): arr[0] is processed, incrementing one slot. Now count records one occurrence. P(1) holds.
- Maintenance: If P(k) holds, step k+1 updates the slot for arr[k], leaving others unchanged. So P(k+1) holds.
- Termination: After n iterations, count[t] gives the total occurrences of value min_val+t in the entire array.



for i from 1 to count.length−1 do
    count[i] <- count[i] + count[i−1]

Loop invariant Q(i):
at the start of iteration i, for every t ≤ i−1, count[t] equals the number of input elements ≤ (min_val + t).

- Initialization: If count.length = 1, loop doesn’t run. count[0] already equals the number of elements ≤ (min_val+0).
- Single iteration (i = 1): After updating, count[1] = elements ≤ (min_val+1). Q(2) holds.
- Maintenance: Assuming Q(i), after updating, count[i] = (occurrences of min_val+i) + (elements ≤ min_val+i−1) = elements ≤ (min_val+i). So Q(i+1) holds.
- Termination: After the loop, for all t, count[t] = number of elements ≤ (min_val+t). The last entry equals n.



output <- array of length n
for num in reverse(arr) do
    idx <- count[num−min_val] − 1
    output[idx] <- num
    count[num−min_val] <- count[num−min_val] − 1
return output

Loop invariant R(k):
after placing k elements (the last k of arr) into output:
1. The suffix output[n−k … n−1] is sorted and contains exactly those k elements.
2. For each value v, count[v−min_val] = remaining occurrences of v in the unprocessed prefix of arr.

- Initialization (k = 0): No elements placed, suffix is empty (sorted), count holds full frequencies.
- Single iteration (k = 1): arr[n−1] is placed in its final slot, suffix of length 1 is sorted, count updated correctly.
- Maintenance: Assuming R(k), the next element arr[n−1−k] is placed just before the current suffix, extending it while keeping it sorted. Count updated correctly. R(k+1) holds.
- Termination (k = n): Entire output array is filled, fully sorted, and contains all n input elements.

i = 1
while i <= n do {
small = i
j = i + 1
while j <= n do {
if A\[j] < A\[small] then small = j
j = j + 1
}
swap A\[i] and A\[small]
i = i + 1
}

Inner Loop Analysis:
Invariant I(j): At any iteration of the inner loop while j <= n, small always points to the index of the smallest element within the subarray A[i…j−1].

- Initialization: Before the first comparison, j is set to i + 1 and small is i. The subarray A[i…i] contains only one element, so small = i correctly identifies the minimum.
- Single Iteration: After the first comparison (when j = i + 1), A[j] is compared with A[small]. If A[i+1] < A[i], small is updated toi+1; otherwise, it remains i. Either way, small correctly points to the smallest element in A[i…i+1].
- Maintenance: Suppose the invariant is true at the start of some iteration j, comparing A[j] with A[small] ensures that small points to the minimum in A[i…j] after the comparison. Incrementing j prepares for the next element, so the invariant continues to hold for j+1.
- Termination: when j exceeds n, the loop stops, and small identifies the minimum element in A[i…n].

Outer Loop Analysis:
Invariant O(i): At the start of each outer loop iteration while i <= n, the subarray A[1…i−1] contains the smallest i−1 elements in sorted order, while A[i…n] contains the remaining elements in any order.

- Initialization (i = 1): Before any iteration, the subarray A[1…0] is empty (trivially sorted), and all elements are in A[1…n]. Therefore, the invariant holds.
- First Iteration: The inner loop identifies the smallest element in A[1…n] and swaps it with A[1]. Now, A[1] contains the smallest element, and A[2…n] contains the rest. The invariant holds for i = 1.
- Maintenance: Assume the invariant holds at iteration i < n, the inner loop finds the minimum in A[i…n] and swaps it with A[i]. Consequently, A[1…i] contains the smallest i elements in sorted order, while the remaining elements are in A[i+1…n]. Incrementing i preserves the invariant.
- Termination: When i becomes n+1, the outer loop ends, and the entire array A[1…n] is sorted in ascending order.

a.)
Let orig represent the initial state of the array arr before any swaps. Just before each iteration of the loop, with pointers left and right, the following conditions hold:

- For every index k where 0 <= k < left: arr\[k] = orig\[n – 1 – k]
- For every index k where right < k <= n–1: arr\[k] = orig\[n – 1 – k]
- For every index k where left <= k <= right: arr\[k] = orig\[k]

b.)
Initialization (0 iterations): Initially, left = 0 and right = n–1. The prefix arr[0…left–1] and suffix arr[right+1…n–1] are empty, so the first two conditions are trivially satisfied. The middle section arr[0…n–1 is identical to orig[0…n–1], so the third condition is also satisfied.

Maintenance (1 or more iterations):Suppose the invariant is true at the start of an iteration with pointers (left,right). We perform:


swap arr[left] and arr[right]
left += 1
right -= 1


Before swapping, arr[left] = orig[left] and arr[right] = orig[right]. After the swap and updating the pointers, the reversed prefix and suffix each grow by one element, while the remaining middle still matches the original. This ensures the invariant continues to hold for the updated (left,right) values.

c.)
Define a variant function V(left, right) = right – left.

- Initially, V(0, n–1) = n–1 >= 0.
- Each loop iteration updates left and right as left += 1 and right -= 1, resulting in V' = (right–1) – (left+1) = (right–left) – 2 = V – 2.
- V decreases by 2 with every iteration and remains >= –1. Once right – left < 1, the condition left < right becomes false.
- Since V is bounded below, the loop cannot continue indefinitely and must eventually terminate.

sum = 0
for i = 1 to n do
sum = sum + (2·i – 1)
end

We claim the following loop invariant holds at the start of each iteration with index i:
invariant: sum = (i – 1)^2
Just before adding 2·i – 1, sum already equals the square of one less than the current loop index.

Before the very first iteration, i = 1 and sum was set to 0. We check:
right side: (1 – 1)^2 = 0
Left side: sum = 0
Thus the invariant holds at the start of iteration 1.

sum = (i – 1)^2 is true. The loop body then executes:
sum = sum + (2·i – 1)


substitute the inductive hypothesis:
sum' = (i – 1)^2 + (2i – 1)
=i^2 – 2i + 1 + 2i – 1
= i^2

After that line, sum = i^2. The for-loop then increments i to i + 1 before rechecking the condition. So, at the start of the next iteration (index i + 1), we have:
sum = i^2 = ((i + 1) – 1)^2

the invariant holds for i + 1. This covers both the “one iteration” check and the maintenance step.
When the loop finishes, i has just been advanced past n, so no more iterations occur. By the invariant at that point,
sum = n^2.
